# Web evidence quality

Implement agreed points 2–6; section-aware extraction (point 1) is excluded.

- Report access separately from truncation, extraction method, anchor presence,
  rendered readiness, and exact stopping limits. Preserve metadata through the
  child protocol and output fitting; never claim an unread section was extracted.
- Guide adaptive one/two-page reads, retain larger deliberate batches, and expose
  exhausted budgets as terminal for that operation without another browser call.
- Raise default/example total evidence to 48,000; retain 8,000 per page and count
  ceilings. Validate serialized-output accounting and five-page capacity.
- Offer explicit rendered reads after a static attempt, requiring named visible
  content with a bounded wait. Keep public proxy, sandbox, download/scheme blocks,
  anonymous profiles and cancellation cleanup. Never render-retry a challenge.
- Replace generic failure notices with evidence-based search/page failure and
  limit summaries, retaining usable evidence and exact source diagnostics.

Verification: focused tests, full suite and Ruff; real Chromium tests on Ubuntu
for delayed dynamic content, timeout, challenge/private access, static isolation,
and process/profile cleanup. Record native and local results separately.
